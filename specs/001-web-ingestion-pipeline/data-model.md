# Data Model: Website URL Ingestion Pipeline

## Content Chunk Entity

**Description**: A segment of extracted text from the textbook website with associated metadata

**Fields**:
- `chunk_id` (string): Unique identifier for the content chunk
- `url` (string): Original URL where the content was found
- `module` (string): Module identifier extracted from URL or page metadata
- `section` (string): Section identifier extracted from page structure
- `content` (string): The actual text content of the chunk
- `created_at` (datetime): Timestamp when chunk was created
- `updated_at` (datetime): Timestamp when chunk was last updated

**Validation Rules**:
- `chunk_id` must be unique
- `url` must be a valid URL format
- `content` must not be empty
- `content` length must be within chunk size limits (e.g., 1000 characters max)

## Vector Embedding Entity

**Description**: Numerical representation of content chunk generated by Cohere embedding models

**Fields**:
- `embedding_id` (string): Unique identifier that matches the content chunk
- `vector` (list[float]): The actual embedding vector (1024 dimensions for Cohere)
- `model` (string): Name of the embedding model used
- `created_at` (datetime): Timestamp when embedding was generated

**Validation Rules**:
- `embedding_id` must correspond to an existing content chunk
- `vector` must have the correct dimensions (1024 for Cohere embed-multilingual-v3.0)
- `vector` values must be normalized floats

## Metadata Entity

**Description**: Structured information associated with each vector embedding

**Fields**:
- `chunk_id` (string): Reference to the content chunk
- `url` (string): Original URL (duplicated for query efficiency)
- `module` (string): Module identifier
- `section` (string): Section identifier
- `source` (string): Source identifier for the content
- `created_at` (datetime): Timestamp when metadata was created

**Validation Rules**:
- All fields must have values (no nulls)
- `chunk_id` must reference an existing content chunk
- `module` and `section` should follow textbook structure conventions

## Pipeline Configuration Entity

**Description**: Settings that control the ingestion, processing, embedding, and storage operations

**Fields**:
- `pipeline_id` (string): Unique identifier for the pipeline configuration
- `sitemap_url` (string): URL of the sitemap to process
- `chunk_size` (int): Size of text chunks (default: 1000)
- `chunk_overlap` (int): Overlap between chunks (default: 200)
- `embedding_model` (string): Name of the embedding model to use
- `qdrant_collection` (string): Name of the Qdrant collection
- `last_run` (datetime): Timestamp of last pipeline execution
- `status` (string): Current status of the pipeline (e.g., "idle", "running", "failed")

**Validation Rules**:
- `sitemap_url` must be a valid URL
- `chunk_size` must be positive integer
- `chunk_overlap` must be less than `chunk_size`
- `status` must be one of predefined values

## Relationships

- One Content Chunk → One Vector Embedding (1:1)
- One Content Chunk → One Metadata (1:1)
- One Pipeline Configuration → Many Content Chunks (1:many)

## State Transitions (if applicable)

The ingestion pipeline follows these states:
1. `idle` → `fetching_urls`: When pipeline starts
2. `fetching_urls` → `extracting_content`: When URL fetching completes
3. `extracting_content` → `chunking`: When content extraction completes
4. `chunking` → `embedding`: When chunking completes
5. `embedding` → `storing`: When embedding generation completes
6. `storing` → `idle`: When storage completes
7. Any state → `failed`: When errors occur (with error details stored)
