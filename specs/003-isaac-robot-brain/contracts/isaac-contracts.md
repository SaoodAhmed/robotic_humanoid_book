# API Contracts: Module 3 - The AI-Robot Brain (NVIDIA Isaac)

## Overview
This document defines the API contracts for the Isaac-based services in Module 3. Since this is primarily an educational module about using Isaac Sim, Isaac ROS, and Nav2, the "APIs" are mainly ROS 2 topics, services, and actions that students will interact with.

## Isaac ROS VSLAM Service Contracts

### 1. Visual SLAM Pose Estimation Service

#### Topic: `/visual_slam/tracking/pose`
- **Type**: `geometry_msgs/PoseStamped`
- **Direction**: Publisher (Isaac ROS) / Subscriber (Student code)
- **Purpose**: Provides 6-DOF pose estimates from visual SLAM processing
- **Performance**: 10-30 Hz depending on scene complexity
- **Message Structure**:
  ```yaml
  header:
    stamp:
      sec: int32
      nanosec: uint32
    frame_id: string  # Usually "map" or "odom"
  pose:
    position:
      x: float64
      y: float64
      z: float64
    orientation:
      x: float64
      y: float64
      z: float64
      w: float64
  ```

#### Topic: `/rgb/image_raw`
- **Type**: `sensor_msgs/Image`
- **Direction**: Publisher (Isaac Sim) / Subscriber (Isaac ROS)
- **Purpose**: Raw RGB camera images for VSLAM processing
- **Performance**: Up to 30 Hz
- **Message Structure**:
  ```yaml
  header:
    stamp:
      sec: int32
      nanosec: uint32
    frame_id: string  # Camera frame ID
  height: uint32
  width: uint32
  encoding: string  # Usually "rgb8" or "bgr8"
  is_bigendian: uint8
  step: uint32
  data: uint8[]  # Image data
  ```

#### Topic: `/visual_slam/map`
- **Type**: `nav_msgs/OccupancyGrid`
- **Direction**: Publisher (Isaac ROS) / Subscriber (Nav2)
- **Purpose**: Map generated by visual SLAM for navigation
- **Message Structure**:
  ```yaml
  header:
    stamp:
      sec: int32
      nanosec: uint32
    frame_id: string
  info:
    map_load_time:
      sec: int32
      nanosec: uint32
    resolution: float32
    width: uint32
    height: uint32
    origin:
      position:
        x: float64
        y: float64
        z: float64
      orientation:
        x: float64
        y: float64
        z: float64
        w: float64
  data: int8[]  # Map data (-1: unknown, 0: free, 100: occupied)
  ```

## Nav2 Navigation Service Contracts

### 2. Navigation Action Server

#### Action: `/navigate_to_pose`
- **Type**: `nav2_msgs/action/NavigateToPose`
- **Purpose**: Send navigation goals to the robot
- **Request Structure**:
  ```yaml
  pose:
    header:
      stamp:
        sec: int32
        nanosec: uint32
      frame_id: string  # Usually "map"
    pose:
      position:
        x: float64
        y: float64
        z: float64
      orientation:
        x: float64
        y: float64
        z: float64
        w: float64
  behavior_tree: string  # Optional behavior tree ID
  ```

#### Action: `/follow_waypoints`
- **Type**: `nav2_msgs/action/FollowWaypoints`
- **Purpose**: Follow a sequence of waypoints
- **Request Structure**:
  ```yaml
  poses: array
    - header:
        stamp:
          sec: int32
          nanosec: uint32
        frame_id: string
      pose:
        position:
          x: float64
          y: float64
          z: float64
        orientation:
          x: float64
          y: float64
          z: float64
          w: float64
  ```

## Isaac Sim Dataset Generation Services

### 3. Synthetic Dataset Generation

#### Service: `/replicator/generate_dataset`
- **Type**: Custom service for dataset generation
- **Purpose**: Trigger synthetic dataset generation in Isaac Sim
- **Request Parameters**:
  - `scene_path`: Path to USD scene file
  - `output_path`: Directory for output dataset
  - `num_samples`: Number of samples to generate
  - `sensors`: Array of sensors to use (RGB, depth, semantic segmentation)
  - `randomization`: Randomization parameters for textures, lighting, etc.

#### Topic: `/dataset_generator/status`
- **Type**: `std_msgs/String`
- **Direction**: Publisher (Dataset generator) / Subscriber (Monitoring)
- **Purpose**: Report status of dataset generation process
- **Message Values**: "idle", "generating", "completed", "error"

#### Service: `/perception_pipeline/stop`
- **Type**: `std_srvs/Empty`

- **Request**: Empty
- **Response**: Empty

#### Topic: `/perception_pipeline/status`
- **Type**: `std_msgs/String`
- **Direction**: Publisher (Pipeline) / Subscriber (Monitoring)
- **Purpose**: Report status of perception pipeline

## Humanoid-Specific Navigation Contracts

### 5. Bipedal Humanoid Navigation

#### Parameter: `robot_description`
- **Type**: `string`
- **Purpose**: URDF/XACRO description of the humanoid robot
- **Required for**: Proper kinematic constraints in Nav2

#### Parameter: `kinematic_constraints`
- **Type**: Custom structure
- **Purpose**: Define bipedal-specific movement constraints
- **Structure**:
  ```yaml
  max_step_width: float64  # Maximum width of a step
  max_step_height: float64 # Maximum height of a step
  min_step_length: float64 # Minimum length of a step
  max_turn_angle: float64  # Maximum turning angle per step
  balance_margin: float64  # Safety margin for balance
  ```

## Educational Module Interfaces

### 6. Lab Exercise Interfaces

#### Service: `/module_3/lab_control`
- **Type**: Custom service
- **Purpose**: Control lab exercises for Module 3
- **Commands**:
  - `start_lab_1`: Start Isaac Sim scene creation lab
  - `start_lab_2`: Start Isaac ROS VSLAM lab
  - `start_lab_3`: Start Nav2 integration lab
  - `reset_environment`: Reset simulation to initial state
  - `validate_lab`: Validate completion of current lab

#### Topic: `/module_3/lab_status`
- **Type**: `std_msgs/String`
- **Direction**: Publisher (Lab controller) / Subscriber (Student interface)
- **Purpose**: Report status of lab exercises
- **Message Values**: "not_started", "in_progress", "completed", "failed", "validation_passed", "validation_failed"

## Error Handling and Validation

### 7. Error Reporting

#### Topic: `/module_3/errors`
- **Type**: `std_msgs/String`
- **Direction**: Publisher (System) / Subscriber (Monitoring)
- **Purpose**: Report errors during Isaac Sim, ROS, or Nav2 operations
- **Message Format**: JSON string with error code and description

### 8. Performance Monitoring

#### Topic: `/module_3/performance`
- **Type**: Custom message
- **Purpose**: Report performance metrics for educational purposes
- **Structure**:
  ```yaml
  header:
    stamp:
      sec: int32
      nanosec: uint32
  fps: float64  # Current frames per second
  vslam_rate: float64  # VSLAM processing rate in Hz
  memory_usage: float64  # Memory usage in MB
  cpu_usage: float64  # CPU usage percentage
  gpu_usage: float64  # GPU usage percentage
  ```

## Security and Authentication

### 9. Secure Communication

All ROS 2 communications should implement DDS Security when required for multi-user educational environments. This includes:
- Authentication of nodes joining the ROS graph
- Encryption of sensitive data streams
- Authorization for control commands

## Validation Criteria

### Functional Validation
- VSLAM pose estimation accuracy within acceptable bounds
- Dataset generation completes with required number of samples
- Navigation goals reached within specified tolerance
- Performance metrics meet defined targets (FPS, processing rates)

### Educational Validation
- Students can successfully complete all three lab exercises
- All ROS topics and services are accessible and functional
- Documentation matches actual system behavior
- Transfer learning from synthetic to real-world data is demonstrated
