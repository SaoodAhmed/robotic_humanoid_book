# Data Model: Module 3 - The AI-Robot Brain (NVIDIA Isaac)

## Overview
This document defines the key data entities and structures for Module 3, which focuses on NVIDIA Isaac tools including Isaac Sim, Isaac ROS pipelines, and Nav2 integration for humanoid navigation.

## Core Entities

### 1. Synthetic Dataset
- **Description**: Collection of photorealistic images, depth maps, and annotations generated from Isaac Sim scenes
- **Fields**:
  - `id`: Unique identifier for the dataset
  - `name`: Human-readable name for the dataset
  - `description`: Text description of the dataset contents
  - `created_at`: Timestamp when dataset was generated
  - `scene_reference`: Reference to the Isaac Sim scene used for generation
  - `image_count`: Number of images in the dataset
  - `image_format`: Format of the images (e.g., PNG, JPEG)
  - `depth_maps`: Boolean indicating if depth maps are included
  - `annotations`: Type of annotations included (semantic segmentation, bounding boxes, etc.)
  - `sensor_config`: Configuration of sensors used for data collection
  - `file_path`: Path to the dataset files
  - `size_mb`: Size of the dataset in megabytes
- **Validation rules**:
  - `image_count` must be > 0
  - `size_mb` must be > 0
  - `created_at` must be a valid timestamp
- **Relationships**:
  - Generated from one Isaac Sim Scene
  - Used by multiple Training/Inference Cycles

### 2. Isaac Sim Scene
- **Description**: Photorealistic environment created in Isaac Sim with lighting, physics, and objects
- **Fields**:
  - `id`: Unique identifier for the scene
  - `name`: Human-readable name for the scene
  - `description`: Text description of the scene
  - `usd_path`: Path to the USD file defining the scene
  - `complexity_level`: Enum (basic, intermediate, complex)
  - `object_count`: Number of objects in the scene
  - `lighting_config`: Configuration for scene lighting
  - `physics_properties`: Properties for physics simulation
  - `sensor_positions`: Array of sensor position configurations
  - `render_fps`: Target frame rate for rendering
  - `created_at`: Timestamp when scene was created
  - `updated_at`: Timestamp when scene was last modified
- **Validation rules**:
  - `complexity_level` must be one of the defined enum values
  - `render_fps` must be > 0
  - `object_count` must be >= 0
- **Relationships**:
  - Generates multiple Synthetic Datasets
  - Used by Isaac ROS Pipelines for sensor data

### 3. Isaac ROS Pipeline
- **Description**: Hardware-accelerated perception pipeline connecting Isaac Sim with ROS 2 for VSLAM and sensor processing
- **Fields**:
  - `id`: Unique identifier for the pipeline
  - `name`: Human-readable name for the pipeline
  - `description`: Text description of the pipeline
  - `pipeline_config`: Path to pipeline configuration file
  - `sensor_inputs`: Array of sensor input types (camera, lidar, IMU, etc.)
  - `processing_nodes`: Array of ROS nodes in the pipeline
  - `vslam_algorithm`: Type of VSLAM algorithm used
  - `processing_rate_hz`: Processing rate in Hz
  - `output_topics`: Array of ROS topics the pipeline publishes to
  - `created_at`: Timestamp when pipeline was created
  - `updated_at`: Timestamp when pipeline was last modified
- **Validation rules**:
  - `processing_rate_hz` must be > 0 and <= 30
  - `sensor_inputs` must contain at least one sensor type
- **Relationships**:
  - Processes data from Isaac Sim Scenes
  - Provides inputs to Nav2 Integration
  - Produces Pose Estimates

### 4. Pose Estimate
- **Description**: Position and orientation data produced by VSLAM processing
- **Fields**:
  - `id`: Unique identifier for the pose estimate
  - `timestamp`: When the pose was estimated
  - `position_x`: X coordinate in 3D space
  - `position_y`: Y coordinate in 3D space
  - `position_z`: Z coordinate in 3D space
  - `orientation_x`: X component of orientation quaternion
  - `orientation_y`: Y component of orientation quaternion
  - `orientation_z`: Z component of orientation quaternion
  - `orientation_w`: W component of orientation quaternion
  - `frame_id`: Coordinate frame of the pose
  - `source_pipeline`: Reference to the Isaac ROS Pipeline that generated this
  - `confidence`: Confidence value of the pose estimate (0.0 to 1.0)
- **Validation rules**:
  - `confidence` must be between 0.0 and 1.0
  - Quaternion components must form a valid unit quaternion
  - `timestamp` must be a valid timestamp
- **Relationships**:
  - Generated by Isaac ROS Pipeline
  - Consumed by Nav2 Integration

### 5. Nav2 Integration
- **Description**: Navigation system that consumes Isaac ROS outputs to generate feasible paths for bipedal humanoid robots
- **Fields**:
  - `id`: Unique identifier for the Nav2 configuration
  - `name`: Human-readable name for the configuration
  - `description`: Text description of the Nav2 setup
  - `config_file`: Path to Nav2 configuration file
  - `robot_model`: Reference to the humanoid robot model
  - `kinematic_constraints`: Constraints specific to bipedal locomotion
  - `global_planner`: Algorithm used for global path planning
  - `local_planner`: Algorithm used for local path following
  - `costmap_config`: Configuration for costmap generation
  - `created_at`: Timestamp when configuration was created
  - `updated_at`: Timestamp when configuration was last modified
- **Validation rules**:
  - `kinematic_constraints` must be valid for bipedal robots
  - `robot_model` must reference a valid humanoid model
- **Relationships**:
  - Consumes Pose Estimates from Isaac ROS Pipeline
  - Generates Navigation Paths

### 6. Navigation Path
- **Description**: Feasible path generated by Nav2 for bipedal humanoid locomotion
- **Fields**:
  - `id`: Unique identifier for the path
  - `path_id`: Identifier from Nav2
  - `waypoints`: Array of (x, y, theta) coordinates for the path
  - `path_length`: Length of the path in meters
  - `estimated_duration`: Estimated time to traverse the path
  - `start_pose`: Starting pose for the path
  - `goal_pose`: Goal pose for the path
  - `nav2_config`: Reference to the Nav2 Integration that generated this
  - `created_at`: Timestamp when path was generated
  - `path_status`: Status of the path (valid, invalid, infeasible)
- **Validation rules**:
  - `path_length` must be > 0
  - `estimated_duration` must be > 0
  - `waypoints` must contain at least 2 points
- **Relationships**:
  - Generated by Nav2 Integration
  - Executed by Humanoid Robot

### 7. Training/Inference Cycle
- **Description**: Complete workflow from synthetic data generation through model training to performance evaluation
- **Fields**:
  - `id`: Unique identifier for the cycle
  - `name`: Human-readable name for the cycle
  - `description`: Text description of the training objective
  - `dataset_reference`: Reference to the Synthetic Dataset used
  - `model_type`: Type of model being trained
  - `training_config`: Configuration for training process
  - `synthetic_accuracy`: Accuracy achieved on synthetic test set
  - `real_world_accuracy`: Accuracy achieved on real-world test set
  - `transfer_ratio`: Ratio of real_world_accuracy to synthetic_accuracy
  - `training_duration`: Time taken for training
  - `created_at`: Timestamp when cycle was initiated
  - `completed_at`: Timestamp when cycle was completed
- **Validation rules**:
  - `synthetic_accuracy` must be between 0.0 and 1.0
  - `real_world_accuracy` must be between 0.0 and 1.0
  - `transfer_ratio` must be between 0.0 and 1.0
- **Relationships**:
  - Uses Synthetic Dataset
  - May use results from Nav2 Integration for navigation tasks

## State Transitions

### Synthetic Dataset
- `created` → `validated` → `used_in_training` → `archived`
- Validation step ensures the dataset meets quality requirements

### Isaac ROS Pipeline
- `configured` → `running` → `processing` → `stopped` → `archived`
- May cycle between running and stopped states during operation

### Navigation Path
- `planned` → `validating` → `approved` → `executing` → `completed`
- May transition to `invalidated` if obstacles are detected during execution

## Data Flow Diagram

```
Isaac Sim Scene → Synthetic Dataset → Training/Inference Cycle
                ↓
Isaac ROS Pipeline → Pose Estimate → Nav2 Integration → Navigation Path
```
