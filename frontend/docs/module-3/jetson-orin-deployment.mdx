# Jetson/Orin Deployment Guide: From Simulation to Hardware

## Overview

This guide covers the process of transferring models, algorithms, and workflows developed in the Isaac Sim → Isaac ROS → Nav2 pipeline to actual Jetson/Orin-class hardware for deployment on physical humanoid robots. The transfer process involves optimizing models for edge inference, adapting simulation-based algorithms to real-world constraints, and ensuring reliable operation on resource-constrained platforms.

## Learning Objectives

After completing this guide, students will be able to:
- Understand the differences between simulation and real-world deployment
- Optimize perception models for Jetson/Orin edge inference
- Adapt navigation algorithms for real-world sensor data and constraints
- Deploy Isaac ROS pipelines to Jetson/Orin hardware platforms
- Validate performance and reliability of deployed systems

## Prerequisites

Before proceeding with hardware deployment, ensure you have:
- Completed Module 3 simulation exercises with Isaac Sim and Isaac ROS
- Trained perception models using synthetic data from Isaac Sim
- Validated navigation algorithms in simulation
- Access to Jetson AGX Orin, Jetson Orin NX, or Jetson Orin Nano development kit
- Understanding of embedded systems and real-world robotics constraints

## Hardware Requirements

### Jetson Platform Options

1. **Jetson AGX Orin (Recommended)**:
   - 64-core ARM v8.2 CPU
   - 2048-core NVIDIA GPU
   - 32GB or 64GB LPDDR5 memory
   - Up to 275 TOPS AI performance
   - Best for complex perception and navigation tasks

2. **Jetson Orin NX**:
   - 8-core ARM v8.2 CPU
   - 1024-core NVIDIA GPU
   - 8GB or 16GB LPDDR5 memory
   - Up to 100 TOPS AI performance
   - Good balance of performance and power consumption

3. **Jetson Orin Nano**:
   - 4-core ARM v8.2 CPU
   - 512-core NVIDIA GPU
   - 4GB or 8GB LPDDR4x memory
   - Up to 40 TOPS AI performance
   - Cost-effective for simpler tasks

### Additional Hardware Requirements
- Compatible carrier board with sufficient I/O for robot sensors
- Power supply appropriate for robot platform
- Real sensors (cameras, LiDAR, IMU) matching simulation specifications
- Network connectivity for development and debugging

## Model Optimization for Edge Deployment

### TensorRT Conversion

To optimize perception models for Jetson/Orin platforms, convert them to TensorRT format:

```bash
# Install TensorRT tools
sudo apt update
sudo apt install tensorrt tensorrt-dev python3-tensorrt

# Convert ONNX model to TensorRT
trtexec --onnx=model.onnx --saveEngine=model.plan --fp16 --workspace=2048
```

### Model Quantization

Reduce model size and improve inference speed using quantization:

```python
import tensorrt as trt
import pycuda.driver as cuda
import pycuda.autoinit

def create_quantized_engine(onnx_file_path, engine_file_path):
    """Create a quantized TensorRT engine from ONNX model"""
    # Create TensorRT logger
    logger = trt.Logger(trt.Logger.WARNING)

    # Create builder and network
    builder = trt.Builder(logger)
    network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
    config = builder.create_builder_config()

    # Enable INT8 quantization
    config.set_flag(trt.BuilderFlag.INT8)

    # Parse ONNX model
    parser = trt.OnnxParser(network, logger)
    with open(onnx_file_path, 'rb') as model:
        parser.parse(model.read())

    # Build engine
    engine = builder.build_engine(network, config)

    # Save engine
    with open(engine_file_path, 'wb') as f:
        f.write(engine.serialize())

    return engine
```

## Deployment Workflow

### 1. Cross-Compilation Setup

Set up cross-compilation for Jetson platforms:

```bash
# Install cross-compilation tools
sudo apt install crossbuild-essential-arm64

# Set up Docker for cross-compilation
docker run --rm --privileged multiarch/qemu-user-static --reset -p yes

# Build for ARM64 architecture
colcon build --merge-install --cmake-args -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=/opt/ros/humble/share/ament_cmake_cross_compile/cmake/toolchain.arm64.cmake
```

### 2. Container-Based Deployment

Use Docker containers for consistent deployment:

```dockerfile
# Dockerfile for Isaac ROS on Jetson
FROM nvcr.io/nvidia/isaac-ros:ros-humble-isaac-ros-main as base

# Install additional dependencies
RUN apt-get update && apt-get install -y \
    ros-humble-navigation2 \
    ros-humble-nav2-bringup \
    python3-pip \
    && rm -rf /var/lib/apt/lists/*

# Copy application code
COPY . /app
WORKDIR /app

# Install Python dependencies
RUN pip3 install -r requirements.txt

# Set environment variables
ENV NVIDIA_VISIBLE_DEVICES=all
ENV NVIDIA_DRIVER_CAPABILITIES=compute,utility
ENV NVIDIA_REQUIRE_CUDA="cuda>=11.0"

# Set entrypoint
ENTRYPOINT ["ros2", "launch", "my_robot_bringup", "jetson_launch.py"]
```

## Troubleshooting Common Issues

### Issue 1: Performance Degradation
- **Symptoms**: Lower frame rates, delayed responses
- **Solutions**:
  - Reduce model complexity
  - Lower sensor data rates
  - Optimize algorithm parameters

### Issue 2: Memory Constraints
- **Symptoms**: Out of memory errors, system instability
- **Solutions**:
  - Reduce buffer sizes
  - Use memory pooling
  - Optimize data structures

### Issue 3: Sensor Calibration
- **Symptoms**: Inaccurate perception or navigation
- **Solutions**:
  - Recalibrate sensors
  - Update camera parameters
  - Verify TF transforms

## Best Practices

1. **Start Simple**: Begin with basic functionality and gradually add complexity
2. **Monitor Resources**: Continuously monitor CPU, GPU, and memory usage
3. **Validate Safety**: Ensure all safety mechanisms are in place
4. **Test Incrementally**: Test each component before integrating
5. **Document Differences**: Keep track of simulation vs. reality differences
