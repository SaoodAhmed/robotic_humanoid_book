# Language-to-Action Translation

## Overview
This document describes the implementation of language-to-action translation in the Vision-Language-Action (VLA) system. This component uses a large language model to translate natural language goals into ordered ROS 2 action plans, enabling sophisticated robot behaviors from simple voice commands.

## Architecture

The language-to-action translation pipeline consists of the following components:

1. **Command Preprocessing**: Cleans and standardizes the input command
2. **Context Enrichment**: Adds environmental and robot capability context
3. **LLM Processing**: Translates natural language to action sequences using OpenAI
4. **Action Validation**: Ensures generated actions are valid and executable
5. **Plan Formatting**: Structures the action plan for ROS 2 execution
6. **Guardrail Enforcement**: Ensures safety and appropriateness of actions

```python
                return False, f"Action {i} must be an object"

                return False, f"Action {i} must have a 'type' property"

            if 'parameters' not in action:
                return False, f"Action {i} must have a 'parameters' property"

            action_type = action['type']

                return False, f"Action type '{action_type}' not supported by robot"
```

## LLM Integration

### Prompt Engineering
The system uses carefully crafted prompts to guide the LLM in generating appropriate action sequences:

```python
class VLAActionPrompter:
    def __init__(self):
        self.system_prompt = """
        You are an expert robotics planner. Your task is to convert natural language commands into structured action sequences for a humanoid robot in a simulated environment.

        Rules:
        1. Always return a valid JSON array of action objects
        2. Each action must have 'type' and 'parameters' properties
        3. Use ROS 2 compatible action types: navigate_to_pose, detect_object, grasp_object, release_object, rotate, speak, wait, perceive_environment
        4. Include error handling and validation in your plans
        5. Account for the robot's physical limitations
        6. Consider environmental constraints and obstacles
        7. If the command is ambiguous, ask for clarification or make reasonable assumptions
        8. Prioritize safety in all generated actions
        9. Ensure action sequences are executable in the given environment
        """

    def create_command_prompt(self, command: str, context: Dict) -> List[Dict]:
        """
        Create a complete prompt for the LLM with system context and user command
        """
        user_prompt = f"""
        Command: "{command}"

        Environmental Context:
        {json.dumps(context.get('environment', {}), indent=2)}

        Robot Capabilities:
        {json.dumps(context.get('capabilities', {}), indent=2)}

        Please generate a sequence of actions to fulfill this command. Return only the JSON array of actions.
        """

        return [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": user_prompt}
        ]
```

## Action Planning Strategies

### Sequential Planning
For simple commands, the system generates a linear sequence of actions:

```
Command: "Go to the kitchen"
Plan: [navigate_to_pose(kitchen_location)]
```

### Hierarchical Planning
For complex commands, the system breaks them into sub-tasks:

```
Command: "Find the red ball and bring it to me"
Plan: [
  perceive_environment(),
  detect_object("red ball"),
  navigate_to_pose(ball_location),
  grasp_object("red ball"),
  navigate_to_pose(user_location),
  release_object("red ball")
]
```

### Context-Aware Planning
The system considers environmental context to generate appropriate actions:


## Error Handling and Recovery

### Ambiguous Command Handling
When commands are unclear, the system can request clarification:

1. Detect ambiguity using pattern matching or LLM assessment
2. Generate appropriate clarification request
3. Wait for user to provide more specific information
4. Retry action planning with clarified command

### Plan Validation and Correction
Before execution, the system validates each action:

1. Check action type is supported
2. Validate parameter completeness and correctness
3. Verify environmental feasibility
4. Apply safety and appropriateness filters
5. Generate corrected plan if needed
